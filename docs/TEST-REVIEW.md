# ContentBridge v0.3.0.4 测试审核清单

> 分支测试版本 `v0.3.0.4`（分支 `v0.3.0.1`）——在 v0.3.0.3 基础上修复第三轮测试发现的两个问题：
>
> 1. **docker 版（4.10.2.0）设置页报错 `viewController.onBeginResume is not a function`**：
>    4.10 web 在视图转场时**无守卫直调**该钩子，缺失即抛错卡页；而 4.8/4.9 web 把同名属性当**真值标记**
>    （一旦存在就认为控制器自带转场、跳过旧视图隐藏——直接补空钩子会双视图叠加）。
>    修复 = **判代条件定义**：仅当 4.10 的页面标记（`needsPageEvents` + `page-hidden`，构造控制器前打上、
>    4.8/4.9 零命中）存在时才补空钩子——4.10 不再报错，4.8/4.9 行为一字不变。
> 2. **社区版（4.9.0.42）计划任务「同步外部内容源」0 秒失败**：代码侧全路径复核完毕——
>    「未配置媒体库根目录」「无启用数据源」都不会让任务失败；0 秒即失败只剩两类：
>    **媒体库根目录不可用**（建目录瞬间抛错）或**数据源连接瞬间失败**（拒绝连接/DNS 等，逐源汇总后任务报错）。
>    两者都把原因写进了任务错误详情——**需要你把错误原文发我**（取证方法见下），我据此收尾。
>
> 测试通过后随 EMBY 合并回 main，统一按 `main-v0.4.0` 正式发版。

## 测试前请提供一份定位材料（第三轮遗留）

**社区版计划任务失败的错误原文**：控制台 → 计划任务 → 「同步外部内容源」→ 点开最近一次（已失败）的运行记录，
把错误详情文字复制或截图发我。文案对应根因一目了然：

- 「**媒体库根目录不可用（路径）：原因……**」→ 媒体库根目录问题（非绝对路径 / 磁盘不存在 / 无写权限）；
- 「**N 个数据源同步失败：源名: 原因；……**」→ 数据源连接/接口问题（原因里带具体网络错误，如拒绝连接）；
- 若是「Object reference not set……」之类裸异常 → 代码问题，发我后直接修。

> docker 设置页若还有残留异常：先 **Ctrl+F5 强制刷新**（浏览器可能缓存旧脚本）再复测；不行请 F12 → Console 截图。
