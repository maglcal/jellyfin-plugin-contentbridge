# ContentBridge v0.3.0.3 测试审核清单

> 分支测试版本 `v0.3.0.3`（分支 `v0.3.0.1`）——在 v0.3.0.2 基础上修复第二轮测试发现的两个问题：
>
> 1. **官方版同步外部源报错**：同步链路错误语义重做——媒体库根目录不可用会抛出**带路径和原因的明确错误**；
>    单个数据源失败不再只写日志，而是汇总进同步结果；「立即同步」改为**等待完成并回显结果**
>    （成功 N 个 / 失败 M 个 + 具体错误文本），计划任务里失败也会显示每个数据源的错误原因。
> 2. **docker 版设置页仍空白**：加载链加固——控制器改**零 AMD 依赖**（依赖解析失败会让页面永远卡住）、
>    页面根同时匹配两种宿主选择器、增加内联引导双通道（旧版宿主执行内联脚本时动态加载同一核心）、
>    所有失败路径都写到页面状态行（不再有静默卡死的转圈）。页面顶部新增诊断提示（Ctrl+F5 强制刷新指引）。
>
> 测试通过后随 EMBY 合并回 main，统一按 `main-v0.4.0` 正式发版。

## 测试前请先回答三个定位问题（第二轮遗留）

1. **docker 版 Emby 的版本号**（在宿主机执行）：
   `docker inspect -f '{{ index .Config.Labels "build_version" }}' <容器名>`
2. **docker 版插件图标现在正常吗？**（判定新 DLL 是否真的已加载——图标是 0.3.0.2 才有的；
   若 docker 侧图标仍是空白，说明容器里跑的还是旧 DLL，需要把新 DLL 覆盖到 plugins 目录后**重启整个容器**）
3. **docker 版是用什么地址访问的？**（`http://局域网IP:端口` 直连，还是域名/反代/https）以及
   上轮「同步报错」的**错误原文**（计划任务错误详情或服务端日志截图）——本轮同步按钮会直接显示错误文本，重测时也能拿到。

> 若 docker 设置页仍空白：先 **Ctrl+F5 强制刷新**（浏览器/Emby 服务缓存了旧页面时会卡住脚本）；
> 还不行请 F12 → Console 截图。页面顶部有诊断提示行：能看到提示行 = HTML 已加载（脚本问题）；整页空白 = 页面资源没加载（缓存/版本问题）。
